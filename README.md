# ToDo Project

간단하지만 강력한 기능을 제공하는 할 일 관리(ToDo) 애플리케이션입니다. 날짜별 할 일 관리, 완료 체크, 수정 및 삭제 기능을 제공하며, 모던한 웹 기술 스택을 활용하여 개발되었습니다.

## 1. 프로젝트 실행 방법

이 프로젝트는 Yarn Workspaces를 사용한 모노레포 구조로 되어 있습니다. 루트 디렉토리에서 의존성을 설치하고 스크립트를 실행할 수 있습니다.

### 사전 요구 사항

- Node.js (v24.13.0)
- yarn

### 설치 (Installation)

```bash
yarn install
```

### Client 실행

```bash
cd client
yarn client
```

### Server 실행

```bash
cd server
yarn server
```

### dev 동시 실행

```bash
yarn dev
```

## 2. 사용한 기술 스택 및 선택 이유

### Frontend

- **React & TypeScript**: 사용자 인터페이스 구축을 위한 라이브러리로, 컴포넌트 재사용성과 타입 안정성을 위해 선택했습니다.
- **Vite**: 빠른 개발 서버 구동과 최적화된 빌드 성능을 제공하여 개발 생산성을 높이기 위해 선택했습니다.
- **Tailwind CSS**: 유틸리티 퍼스트 CSS 프레임워크로, 빠르고 일관된 스타일링을 적용하기 위해 사용했습니다.
- **Context API**: 별도의 상태 관리 라이브러리 없이 React 내장 기능만으로 전역 상태(할 일 목록, 모달 등)를 효율적으로 관리하기 위해 선택했습니다.

### Backend

- **Node.js & Express**: 비동기 처리에 강하고 가벼운 웹 프레임워크로, RESTful API 서버를 빠르게 구축하기 위해 선택했습니다.
- **Layered Architecture**: Controller, Service, Repository 패턴을 적용하여 비즈니스 로직과 데이터 접근 계층을 분리, 유지보수성을 높였습니다.
- **Dependency Injection (DI)**: 의존성 주입을 통해 모듈 간의 결합도를 낮추고, 테스트 용이성과 코드의 유연성을 확보했습니다.

- 대부분의 모델은 `createdAt`, `updatedAt`, `deletedAt`을 분리하여 생성과 수정을 구분하여 저장하도록 설계했습니다.

### Todo (할 일)

- **id**: 고유 식별자 (Number/UUID)
- **title**: 할 일 제목 (String, 필수) - 목록에서 보여지는 주요 정보
- **content**: 할 일 상세 내용 (String) - 추가적인 메모 사항
- **completed**: 완료 여부 (Boolean) - 할 일의 상태 관리
- **date**: 수행 날짜 (Date/String) - 날짜별 할 일 필터링을 위한 필드
- **createdAt**: 생성 일시 (Date)
- **updatedAt**: 수정 일시 (Date)
- **deletedAt**: 삭제 일시 (Date) - Soft Delete 지원

**설계 이유**:
사용자가 날짜별로 할 일을 관리하는 것이 핵심 기능이므로 `date` 필드를 포함하여 날짜별 조회가 가능하도록 설계했습니다. 또한 `title`과 `content`를 분리하여 목록에서는 간략하게, 상세에서는 구체적으로 내용을 확인할 수 있도록 구조화했습니다.

### TodoCategory (할 일 카테고리)

- **id**: 고유 식별자 (Number)
- **name**: 카테고리 이름 (String, 필수)
- **parentId**: 상위 카테고리 ID (Number, 선택) - 계층형 구조 지원
- **createdAt**: 생성 일시 (Date)
- **updatedAt**: 수정 일시 (Date)
- **deletedAt**: 삭제 일시 (Date) - Soft Delete 지원

**설계 이유**:
할 일을 체계적으로 분류하기 위해 카테고리 기능을 도입했습니다. `parentId`를 통해 하위 카테고리를 가질 수 있는 계층형 구조를 지원하며, `deletedAt`을 사용하여 실수로 삭제된 데이터를 복구할 수 있도록 Soft Delete 방식을 채택했습니다.

### ErrorDefinition (에러 정의)

- **code**: 에러 코드 (String) - 예: 'TODO_001', 'CAT_003'
- **status**: HTTP 상태 코드 (Number)
- **message**: 에러 메시지 (String)

**설계 이유**:
배포 없이 바로 에러 코드 및 메세지를 수정할 수 있게 하며, 애플리케이션 전반에서 발생하는 에러를 일관성 있게 관리하기 위해 에러 정의 모델을 별도로 설계했습니다.

## 4. 개발 시 고민했던 점

### FSD(Feature-Sliced Design) 기반 폴더 구조

### React Page의 폴더 구조

단순한 기능별 분리가 아닌, 도메인(기능) 단위로 응집도를 높이기 위해 `pages/TodoPage` 내부에 `context`, `hooks`, `components`, `sections`를 배치했습니다. 이를 통해 해당 페이지와 관련된 로직을 한곳에서 관리하고 유지보수성을 향상시켰습니다.

### API Client 추상화 및 의존성 주입

`Axios`를 직접 컴포넌트에서 사용하지 않고, `ApiClient` 인터페이스와 구현체로 분리했습니다. 이를 통해 API 호출 로직을 캡슐화하고, 향후 HTTP 클라이언트가 변경되거나 테스트 시 Mocking이 필요할 때 유연하게 대처할 수 있도록 설계했습니다.

## 5. 아쉬웠던 점

### 시간 부족

- 개인 사정으로 인하여 실제 개발 시간은 약 10시간 정도 되었습니다.
